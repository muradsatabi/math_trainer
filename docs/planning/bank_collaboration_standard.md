# Правила совместной работы с банком заданий

Версия стандарта: 1. Дата: 10 октября 2026 года.

Канонический источник: `muradsatabi/math_trainer`, ветка `main`, файл `docs/planning/bank_collaboration_standard.md`. Другие копии не редактируются независимо.

Статус: согласованные принципы взаимодействия; техническая реализация неполная. Поля заданий и окончательная схема банка пока не утверждены. Этот документ не утверждает новые задания или методические ограничения проверки.

## Общий процесс

В проекте «Математика — методика и банк заданий» каждая тема разрабатывается в отдельном чате. Все тематические чаты пополняют единый логический банк. Один файл на тему предложен как способ организации и требует согласования физической модели. Утверждённый банк в репозитории muradsatabi/math_trainer является общим источником для печати и Flutter; независимо редактируемые копии банка не создаются.

Владелец обсуждает задания и явно утверждает конкретное содержание. После утверждения целевой процесс должен сохранять именно это содержание, выполнять проверки и обеспечивать доступ для чата печати и локального проекта без ручного скачивания, копирования данных или отдельной команды переноса. Пока техническая цепочка не настроена и не проверена, чат не должен объявлять автоматическое сохранение завершённым.

## Роли чатов

Тематический чат разрабатывает задания своей темы с владельцем, различает предложения и утверждённое содержание и выполняет согласованную процедуру сохранения. Чат «Запуск новой темы» готовит стартовый промпт для новой темы по действующим общим правилам. Чат печати читает утверждённые задания для выбора, показа и подготовки материалов по запросу владельца. Чаты разработки приложения проектируют и реализуют использование банка, не придумывая задания или методику.

## Проверка актуальности

Перед дополнением, исправлением или сохранением банка тематический чат заново читает этот файл из текущей ветки `main` через подключённый GitHub и получает актуальные данные. Локальная копия, старое сообщение или документ из ещё не принятого PR не заменяют опубликованную версию. Для операции фиксируется использованный SHA коммита; если правила изменились до записи, совместимость проверяется снова. Чат «Запуск новой темы» делает это перед каждым новым стартовым промптом. Чат печати проверяет правила и формат при работе с банком; инструменты приложения проверяют совместимость при загрузке обновлений. Сообщение «Правила банка заданий изменились» означает перечитать правила. Дополнительное уведомление не требуется для обязательной проверки перед операцией.

Получение актуальных правил — обязательная инструкция, а не гарантия технической возможности любого чата. Если источник недоступен или формат не поддерживается, чат сообщает о препятствии и не сохраняет по памяти или догадкам. Документ не делает фоновые уведомления и синхронизацию настроенными автоматически.

## Изменение общих правил

Предложение может исходить из любого рабочего чата: методики, печати или приложения. Существенные изменения полей, методики и структуры обсуждаются с владельцем. После явного утверждения конкретного изменения публикуется новая версия общего стандарта с описанием изменений. Перед записью проверяется текущая версия, чтобы не затереть параллельные изменения другого чата; при конфликте запись останавливается. Обновление стандарта не даёт разрешения автоматически менять математическое содержание. Утверждение привязывается к конкретному содержанию и версии. Каждый следующий рабочий запрос использует действующую версию; старые инструкции в переписке не заменяют её.

Новый столбец меняет формат; переименование темы меняет каталог. Эти изменения учитываются отдельно и сохраняют устойчивые ID. Старые утверждённые записи не переписываются молча. До изменения формата определяется совместимость и необходимый перенос старых записей; недостающие методические значения не выдумываются.

## Сохранность и проверка

Каталог материала и граф зависимостей — отдельные структуры. Одно микроумение соответствует одному шаблону действия. Каждое задание имеет устойчивый ID. Образец и известные допустимые ответы не считаются исчерпывающим списком. Математическая эквивалентность не заменяет выполнение требуемого действия. Подсказки, объяснения и варианты добавляются только при утверждённом содержании.

Повторная передача должна быть идемпотентной: совпадающие записи не создают дубликаты, различие содержания при той же опубликованной версии является конфликтом. Методическое утверждение отделено от технической публикации. Успех подтверждается принятой версией и ссылкой; ошибка проверки не является публикацией. Незакоммиченные локальные изменения не перезаписываются. Новый контент приложения появляется при следующей сборке.
