# Рабочая карта продукта

Источник: [логика приложения.drawio](sources/логика%20приложения.drawio). Все 46 блоков сохранены в [полной описи](diagram_inventory.md), включая заголовки. Шесть линий имеют только координаты концов, не связаны с ID блоков и расположены как горизонтальные разделители. Их нельзя использовать как переходы приложения. Ниже — редакционная группировка для планирования, не утверждение всей карты к реализации.

## Направления из схемы

| Направление | Сохранённые идеи автора | Рабочий статус |
| --- | --- | --- |
| Учебное ядро | Решение примеров; практика; теория (минимум); теория; проверочное тестирование; анализ ошибок | Практика и разбор ошибок реализованы на демонстрационных данных. Реальный банк, общие проверяющие правила, отдельная теория и проверочное тестирование требуют следующего согласованного этапа |
| Диагностика и маршрут | Входное диагностическое тестирование; траектория; траектория (прогресс по темам); повторение пройденных тем внутри траектории | Принципы графа, диагностики и маршрута закреплены в разделе 11 продуктовых требований. Конкретные алгоритмы и интерфейс не реализованы |
| Навигация и материалы | Темы; список тем по классам; справочник; избранное; блок: дроби | Есть демонстрационный список тем. Каталог по классам, справочник, избранное и отдельный набор по дробям не реализованы; положение темы в классе не задаёт зависимость автоматически |
| Обратная связь об обучении | Прогресс; статистика | Есть демонстрационные проценты и счётчики. Модель освоения, реальные расчёты, сохранение прогресса и отчётность не реализованы |
| Дополнительные учебные опции | Выбор класса; марафон (по определённой теме или заданию); тест на время; задания повышенной сложности (со звёздочкой); режим билетов | Идеи из схемы. Объём, условия, подбор заданий и влияние на маршрут не утверждены |

| Печатные материалы | Материалы для печати | Согласован принцип единого банка для приложения и PDF. Экспорт PDF в интерфейсе пока не реализуется; точные утверждённые шаблоны необходимо получить из методической работы |
| Экзаменационные направления | ВПР; ОГЭ; ЕГЭ | Перспективные идеи; требования и материалы не утверждены для разработки |
| Мотивация и социальные функции | Система награждения; гэмификация; друзья; рейтинг (в классе, в школе) | Идеи из схемы. Не являются разрешением на добавление аккаунтов, публичных результатов или социальных функций |
| Пользовательские режимы | Ученик; родитель; тьютор | Идеи ролей/режимов. Их права, различия и необходимость учётных записей не определены |
| Настройки и поддержка | Настройки; чаты; FAQ; техподдержка; ИИ-чат | Идеи из схемы. Контролируемые исключения маршрута обсуждены в требованиях; отдельные способы доступа, поддержка, ИИ и коммуникации не определены |

Отдельно сохранены организационные заголовки: «МИНИМАЛЬНЫЙ ФУНКЦИОНАЛ», «ДОСТУПНЫЕ ОПЦИИ», «ПЕРСПЕКТИВНЫЕ НАПРАВЛЕНИЯ», «ВИДЫ ЗАДАНИЙ», «РЕЖИМЫ». В исходнике под «Минимальным функционалом» расположены блок «Дроби», решение примеров, траектория, минимум теории и проверочное тестирование. Это авторский набросок состава продукта; он не меняет текущую границу первой версии — режим «Практика».

## Как разделить будущую архитектуру

| Часть | Ответственность |
| --- | --- |
| Единый банк | Утверждённое математическое содержание с устойчивыми ID и версиями, общее для приложения и печати |
| Каталог | Поиск и организация материала по предмету, главе, разделу, теме и микроумению; привязки к классам уточняются отдельно |
| Граф умений | Утверждённые зависимости и связи возврата, независимые от расположения материала в каталоге |
| Результаты ученика | Попытки, диагностические выводы и подтверждение освоения; отдельно от банка заданий |
| Индивидуальный маршрут | Выбор следующего шага по графу и результатам с согласованными исключениями |
| Представления | Практика, диагностика, теория, итоги и печатные материалы; каждое использует общие данные в рамках своих правил |

Это границы ответственности для дальнейшего проектирования, а не требование сразу создавать шесть сервисов, сервер или новые модели Flutter. Идеи марафона, повторения и экзаменационной подготовки в перспективе должны использовать тот же банк, а не отдельные копии заданий.

## Рабочая инструкция для новых функций

Для каждой выбранной идеи сформулировать пользовательскую задачу, минимальный сценарий, используемые данные, критерии проверки и открытые методические вопросы. Проверить согласованность с текущими требованиями и определить небольшой этап. После утверждения обновить основной продуктовый документ; реализацию и проверки отражать в development_status.md. Соседние блоки схемы сами по себе не задают переходы между экранами.

Ближайшая задача — согласовать архитектуру единого банка и небольшой фрагмент графа вынесения общего множителя. Диагностику и индивидуальный маршрут проектировать с учётом графа, но не добавлять в текущую практику до утверждения алгоритмов. Печатные шаблоны не восстанавливать по предположениям. Идеи будущих режимов сохраняются здесь, чтобы не потеряться и не расширять текущий этап автоматически.
