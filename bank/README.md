# Локальный банк: первая реализация

15 октября 2026 года. Банк пока не опубликован в GitHub. Формат является первой технической реализацией по поручению владельца начать работу со всем накопленным содержанием; опубликованный общий стандарт версии 1 пока не обновлён.

## Источник и сохранность

В sources/common_factor_v8.json сохранена точная передача значений 110 строк Excel из Библиотеки методического проекта, полученная через чат «Тема: Вынесение общего множителя за скобки». Все десять столбцов и примечание сохранены. Это архив источника для сверки, а не второй независимо редактируемый банк.

Методический чат заново получил исходный XLSX и сообщил SHA-256 c2dc45578a280fb35b2d358201cd0cb10ae9b9f7e4594a6dcc1a35a801b6c967. Сам XLSX локально не скачивался; этот хэш получен от чата источника. Снимок JSON имеет собственный хэш в manifest.json. Версия источника 8 не является версией формата или задания.

Файлы blocks/ содержат 22 блока по пять заданий. Файлы skills/ содержат исходные названия микроумений. ID заданий ВМ-001–ВМ-110 сохранены. Новые технические ID common_factor_01–common_factor_22 выделены по исходным номерам блоков и не меняют методику. Порядок блоков задан manifest.json, порядок задач — массивами tasks. Каталог учебной программы и граф зависимостей не достраивались. source_section_id сохраняет значения источника; новые названия «Этап 1/2» в данные не внесены.

## Проверки и повторный импорт

Из корня проекта:

```powershell
python tool/import_task_bank.py --check
python tool/test_import_task_bank.py
```

Импорт без --check создаёт только отсутствующие файлы. До любых записей он проверяет весь пакет. Совпадающие записи не дублируются, различия с существующими файлами вызывают конфликт без перезаписи. Этот первоначальный импорт не является механизмом обновления уже опубликованных версий. Для изменений нужен отдельный согласованный перенос с версиями и утверждением; обхода конфликтов нет.

methodical_status=approved передаёт исходное «Согласовано». Техническая публикация учитывается отдельно. Новый импорт не является новым методическим утверждением. Подсказки и отвлекающие ответы не создавались.

## Практика

Настройки находятся в manifest.json: minimum_answers=22, success_window=22, pass_percent=85, extra_tasks_per_error=2. Минимум и окно являются параметрами темы. В первоначальном маршруте показывается одно задание каждого блока, после ошибки добавляются два из того же блока. Ошибка в дополнительном задании также добавляет два. После исчерпания пяти исходных записей они повторяются с прежними ID; генерации нет.

Проверенные дополнительные ответы входят в окно успешности. Для прохождения нужны минимальное число ответов, полный размер окна, посещение всех блоков, отсутствие оставшихся дополнительных заданий и точный порог 85%. Если после первого круга порог не достигнут, практика продолжается по исходным блокам. Это текущая реализация базового маршрута, без графа и диагностики. Процент на экране округляется вниз; прохождение проверяется без округления. Данные текущей сессии находятся в памяти и теряются при обновлении страницы.

Вход в приложение без параметров открывает карточку реальной темы в компоновке V3. Старые экраны доступны через параметр screen для просмотра макетов. Неправильные варианты к банку не утверждены, поэтому реальная практика использует ввод ответа. Экранный конструктор содержит три группы по две колонки и три строки. Дополнительная страница чисел даёт доступ ко всем цифрам 0–9; буквы берутся из исходного выражения. Ввод поддерживает замену выделенного диапазона, удаление символа и очистку. После проверки редактор заблокирован. Полнота формы проверяется отдельно от математической правильности: неполную запись отправить нельзя, полную неверную — можно.

Предыдущее задание открывается только для чтения. Текущая строка и курсор сохраняются при просмотре истории и выходе к темам в пределах открытой сессии; просмотр не добавляет попыток. Значок завершения темы зависит от всех условий прохождения, а не только от высокого процента первых ответов. Итоги связаны с последним решением, закреплением и отдельным разбором реальных ошибок. На последней из нескольких ошибок доступен возврат к первой; при единственной ошибке переходы вперёд отсутствуют. Закрепление показывает исходные названия микроумений и образцы из выполненных заданий, без новых учебных текстов.

Проверка использует точную целочисленную полиномиальную арифметику, принимает образцы из источника и явно указанную альтернативу с технической нормализацией пробелов и символов умножения/минуса. Математически неравные ответы и исходная сумма не проходят. Другие эквивалентные факторизованные формы, правила которых не определены, получают статус «не поддерживается», а не ошибку. Дроби, степени, полные равенства и расширенные формы пока не проверяются. Это ограниченный проверяющий модуль, а не полное решение методических вопросов.

На ошибке доступна исходная правильная запись. После третьей подряд ошибки текущего блока она открывается автоматически. Полноценного утверждённого подробного объяснения нет; образец не выдаётся за него. Последним уточнением владельца подтверждён проходной порог 85% по последним 22 ответам; отдельный порог 82% не применяется. Визуальная проверка браузером пока не подтверждена.

Для отдельной проверки рендера без браузера можно выполнить flutter test --no-pub tool/verify_bank_render_test.dart. Он загружает проектные шрифты и шрифт иконок SDK, сохраняет изображения реального дерева виджетов в docs/verification/bank-*-widget.png. Это изображения тестового рендера, не снимки браузера. Доступ к браузеру остаётся необходимым для подтверждения фактического отображения Web.


## Текущие параметры короткой практики — 16 октября 2026 года

По просьбе владельца для ускорения проверки функций окно успешности и
minimum_answers в манифесте сокращены до 10. Начало — 0/10; ввод ответа
доступен с 7 правильных, добровольное завершение — с 9 правильных.
Завершение не требует всех блоков или отсутствия дополнительных заданий.
Эти поздние правила заменяют прежние условия завершения, описанные выше.
Сохраняются все 22 блока и 110 исходных заданий; содержимое не удалялось.


## Закрепление после ошибки — 16 октября 2026 года

Правило простого добавления заданий выше заменено: после ошибки нужны
два правильных решения того же типа подряд. Каждая новая ошибка начинает
серию заново; после двух верных подряд маршрут переходит дальше.
Техническое поле extra_tasks_per_error=2 сохранено для совместимости и теперь
задаёт длину требуемой серии. Оцениваемые ответы входят в обычное окно успешности;
просмотр истории и неподдерживаемые записи не меняют серию.
Общий механизм PracticeSession применяет правило к любому банку тем.
